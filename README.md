# QQBot HK

Nous Research Hermes Agent 的 QQ Bot 在 Hytron HK 上的独立部署仓库，模型通过现有 Sub2API 提供。

## 配置

生产秘密位于 `/opt/qqbot-hk-deploy/secrets`，不得提交：

- `qqbot.env`：`QQ_APP_ID`、`QQ_CLIENT_SECRET`、`QQ_SCHEDULE_GROUPS`。
- `sub2api-deepseek-api-key`：聚合国模分组 key，同时用于 DeepSeek 与 MiMo；仅在服务器运行环境注入，旧通用和 Muse/MiMo 专用 key 不再注入 QQ bot。
- `QQ_SCHEDULE_GROUPS` 是固定公告的显式目标列表，使用逗号分隔的 QQ 群 OpenID，不能使用数字群号、用户 OpenID、空值或 `*`。固定公告默认禁用。部署会移除旧 `QQ_GROUP_ALLOWED_USERS`，防止 Hermes 环境变量覆盖群专属通配配置。
- 开发体验阶段也使用 QQ 官方生产 API/Gateway；开放平台按“开发体验用户”名单限制可访问账号。

可提交占位模板见 `.env.example`。本机 `.env.local` 被 Git 忽略。

## 运行边界

部署使用以 Hermes Agent v0.21.5（`v2026.9.24`）固定摘要为基础的项目派生镜像。新版原生发现插件；项目以 SHA/哨兵 fail-closed 应用 QQ 语音、Sub2API Chat 推理、帮助、最终输出、异步上下文与 doctor provider 诊断补丁，不复制整个 adapter。安全依赖使用提交的 npm 生成锁文件，镜像构建核对实际安装版本并执行 root、web、ui-tui 和全部 workspaces 四项零漏洞审计；审计不可用同样阻断。构建同时运行真实上游行为 smoke，包括原生权限、模型路由持久化、推理隔离、reset/隐私的 generation 失效和知识库保留。容器不开放宿主机端口、不挂载 Docker socket，只加入 `sub2api_sub2api-network`。

- 私聊：使用 Hermes `dm_policy: pairing`，自动配对已关闭；新的未批准用户进入标准配对码流程。QQ 开放平台仍必须先实际投递该用户消息。
- 群聊回复：允许已由 QQ 适配器和中央网关授权群的官方 `@机器人 + 问题`，也会在平台投递普通群消息时按规则参与求助、分享、观点和吐槽。普通消息先免费过滤，再按同成员聚合，由模型判断是否有自然接话的价值；明确 @ 他人、管理命令和纯表情/收尾不进入主 Agent。
- 同一群共享 Hermes 会话；私聊、其他群和当前群严格隔离。
- 角色采用自然群友风格，可以主动提问和完整表达；不再机械过滤末尾问句，也不再截断主动回复为 180 字。短回复按句子/换行分条，引号或括号内部不拆句；长回复与代码完整保留，以每包最多 1500 字进行传输分段。命令回复也不再最多发送五段。常见 Markdown 统一降级为纯文本。同一轮仅首条显示引用，后续分条保留 QQ 被动回复凭据但不重复引用卡片；失败停止，重试跳过已成功分条；完整发送后只登记一轮回复及其各条消息引用。
- QQ 工具集启用 `web`、`vision`、`skills`、`todo`、`terminal`、`file`；其中 `terminal` 提供 shell 能力，`tts`、`code`、`computer` 不暴露。文件写入受 `HERMES_WRITE_SAFE_ROOT=/opt/data:/tmp` 限制，Hermes credential/project env 路径仍由内置防护拦截。
- QQ 语音输入与输出均关闭：语音附件不进入 STT/模型，`send_voice` 在媒体上传前失败关闭，配置不包含 TTS provider 或音频密钥。普通文本与图片功能不受影响。
- `smart_group_qq` 插件提供静态审核、关键词短路、幂等审计、长期记忆、群知识库和中文 `/help`。模型快捷命令为 `/deepseek`、`/mimo`；推理强度为 `/low`、`/medium`、`/high`、`/xhigh`、`/max`，均只修改当前会话。DeepSeek 将 `xhigh` 映射为实际请求的 `max`。
- 支持 `/` 打开帮助、全角斜杠、斜杠后空格、QQ mention 紧接命令。已明确 @ 机器人的全量群消息也走命令入口；非定向旁听仍不能执行管理命令。忙碌群会话的 `/值日表`、`/all` 等本地命令不再并入聊天队列，原生模型/推理切换沿用 Hermes 的忙碌提示与权限控制；`/reset`、`/new` 保留原生生命周期。群共享会话的待审批操作无法绑定发起成员，因此群内不透传 `/approve`、`/cancel`、`/deny`，需确认的操作请改在私聊执行；私聊 `/help` 优先显示中文菜单，`/值日表` 仅群聊可用。
- `@机器人 /值日表` 按北京时间即时计算本周日到周六的轮值安排；2026 年 9 月 13 日开始，每周日轮换一次，开始前显示首轮预告。该功能不依赖主动群发或模型调用。
- `/summary` 使用模型生成本群摘要、话题、决定、待办和未决问题；每群独立持久化，`/reset` 只清理会话与记忆，不删除知识库。
- `/kb add 标题 | 正文` 添加资料；`/kb list`、`/kb search 关键词`、`/kb remove 文档ID`、`/kb clear confirm` 管理本群知识。支持缓存目录中的 TXT/Markdown/CSV/JSON/YAML/XML/TOML/DOCX，PDF 需镜像提供 `pypdf`。
- 审计表只保存动作元数据，不保存原消息或回复正文。
- 所有机器人已加入、且 QQ 平台允许投递的群均开放非 @ 按需参与。配置通过原生 `group_allow_from: ["*"]` 与 `group_allowed_chats: ["*"]` 分别授权适配器和中央网关；私聊仍要求 pairing，不启用 `QQ_ALLOW_ALL_USERS`。固定定时群发仍禁用。[QQ 官方现行文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)列出全量群消息与主动发送能力；群管理员仍需分别开启接收全部消息与允许主动发送。

### 成员专属记忆与非 @ 消息

- 成员身份记忆使用独立的 `group_members`、`member_memory_facts` 表，按 `(group_id, member_ref)` 隔离；不得把成员私有资料写入群级 `knowledge_documents`。`compaction_jobs` 保存异步压缩任务的游标和重试状态。
- 发布版本的 `member_ref`/`member_digest` 必须由部署态密钥派生，是稳定伪名而不是 QQ OpenID 的截断值；未注入部署态密钥的构建不得上线。原始 OpenID 不写入日志、提示词、指标或生成的 cron 文件。
- 默认只保存成员主动表达、明确确认或通过记忆命令授权的偏好、角色和项目事实；不推断健康、政治、宗教、性取向、财务等敏感属性。成员可查询、撤回和删除自己的记忆，删除必须覆盖画像、事实、来源关联和缓存召回。
- 自动提取的新事实必须附有本次输入中的原文证据，并绑定该成员本条消息的历史行；拒绝缺失/伪造证据及非有限置信度，不把同群后来另一人的消息误认作来源。
- `/纠正记忆：字段=新内容` 的本人确认优先于自动推断。同一归一化字段不因模型分类不同而重复，晚完成的旧消息提取不能覆盖更新来源。回答时先按当前问题相关性召回，再考虑本人确认和更新时间，不只机械取最后几条。
- `/我的记忆` 查看本人在当前群的有效记忆，`/我的记忆 项目` 只列出关键词命中；未同意或已停止记忆时查询不会重新开启记忆。
- 空白或敏感内容的记忆命令不会重新开启已停止的成员记忆。`/停止记忆` 和 `/纠正记忆` 会重置本群当前会话上下文，避免继续沿用旧画像。
- `/忘记我` 会清理本人原文、成员档案/事实、本群机器人回复缓存以及衍生摘要/压缩任务；他人成员原文和知识库保留。清理范围是机器人内部缓存，不是撤回 QQ 客户端消息。持久化失效版本防止清理前尚在运行的摘要、提取或回答再次写回旧内容，即使之后重新同意记忆也不恢复旧任务。
- 非 `@` 消息只在 QQ 开放平台实际投递 `GROUP_MESSAGE_CREATE` 时进入本群 ambient 历史和摘要链路。普通消息按同群同成员进行 2 秒尾沿防抖、第一条起最多等待 5 秒，最多 20 条/6000 字；规则高分直接参与，模糊候选才调用一次低推理分类。默认回复冷却为 0，追问继续聚合；官方 `@机器人` 不等待且会使旧参与判断失效。`@` 其他成员、非 @ 管理命令、纯表情/收尾闲聊保持静默。
- 有内容的陈述、短句与同话题的其他成员消息都会进入参与判断；话题窗口为 120 秒。默认 `ambient.participation.max_interjections_per_minute: 0` 表示不设本地每分钟插话额度，`unanswered_pause_seconds: 0` 表示不因无人回应强制退场，`cooldown_seconds: 0` 表示不施加固定回复冷却。需要时可改为正数恢复这些限制。仍保留同成员 2 秒/最多 5 秒聚合、重复事件过滤、并发队列容量、过期消息丢弃和真实 QQ 平台配额。自由模式由模型按兴趣决定参与，不保证逐条回复。叫名字、官方 @、引用机器人的消息仍是直接会话信号。
- 近期原文、滚动摘要、当前成员事实和知识检索分别受 1600/800/600/1000 字预算约束，原有记忆背景不超过 4000 字；角色人格及状态单独注入（状态序列化预算 3500 字）；当前合并问题另有 6000 字上限。语音附件始终忽略。非 @ 纯图片也可进入参与判断，先免费鉴权/规则过滤，再加载最多最新 5 张真实图片交给分类模型；下载或读取失败则静默，不假装看过图片。所有 QQ 主模型请求（含历史、引用与工具图片）统一只保留最新 5 个图片块，多余图片替换文字占位；不删除用户文件。附件禁止重定向，单文件下载/读取上限 20 MiB。
- 全群开放时新群不需要手工登记 OpenID。若运维主动恢复限制策略，未授权群的 @、加群和允许通知事件仅记录 `group_access_pending` 接入元数据到服务器审计数据库，每群每小时最多一条；不保存正文、不自动授权。
- 群知识检索覆盖本群所有已存片段，采用流式 top-k 保持候选内存有界，不再只检查最新 2000 个片段。当前仍是词面检索，不能等同于 embedding 语义召回。

### 数据保留与删除

`group_history` 是用于摘要和最近上下文的受限原文缓存，不等同于永久聊天档案；当前配置分别使用 `memory.ambient_retention_days`、`memory.addressed_retention_days` 和 `member_memory.fact_retention_days` 控制 ambient、addressed、成员事实的保留期。审计和媒体缓存也必须分别配置保留期，并由定时维护任务执行过期删除。`/reset` 清理当前群会话/历史/群摘要但保留知识库；成员退出或执行删除命令时，还要删除其专属画像和事实。审计仅保留动作元数据，日志、指标和错误信息不得包含消息正文、OpenID、附件签名 URL、提示词或密钥。

QQ 当前“开发体验用户”机制使用生产 API/Gateway，并由开放平台限制体验范围。不要设置旧的 `QQ_SANDBOX` 路由；它会使新增开发体验用户的 C2C 事件无法到达当前网关。

## 常驻角色：小栖

默认角色是喜欢开源玩具、游戏和技术的 AI 电子室友。`config/SOUL.md` 控制人格与真实能力边界；`settings.character.persona` 可覆盖动态注入的人格，同时修改 SOUL 与唤醒词以保持一致。角色用真实互动形成共同经历和熟悉度，精力与好奇心影响表达，虚构宠物/剧情不会变成用户事实。

### 使用方法

群聊管理和玩法命令请 @机器人；自然控制也可以叫名字，例如“小栖，安静一会儿”。私聊直接发送。角色内容保存在当前群，私聊使用独立 `dm:` 命名空间。

自然语言与旧命令共用执行逻辑，不依赖模型猜测配置。群内请 @机器人（或由现有唤醒入口明确叫“小栖”），私聊可直接发送：

| 直接说 | 等效操作 |
| --- | --- |
| 切到 DeepSeek | `/deepseek`，仅当前会话 |
| 切到 MiMo | `/mimo`，仅当前会话 |
| 推理调高 / 推理强度调到最高 | `/high` / `/max`，仅当前会话 |
| 查看当前模型 / 当前推理强度是多少 | Hermes `/model` / `/reasoning` 查询 |
| 安静10分钟 / 安静半小时 / 恢复聊天 | 按时暂停或恢复主动参与；被叫到仍回应 |
| 看看宠物 / 给宠物喂点东西 / 把宠物改名为土豆 | 查询、喂食、改名 |
| 新增目标：部署测试 / 完成目标 部署测试 | 创建目标或按本人目标名称完成 |
| 记住这个梗：电子土豆 / 我选第一个 | 保存梗 / 剧情投票 |
| 查看我的记忆 / 停止记住我 / 删除我的记忆 | 原成员记忆操作 |

配置解析兼容 `/ deepseek`、`／ ＤＥＥＰＳＥＥＫ`、`/mimo`、`/模型 MiMo`、`/模型 DeepSeek`、`/配置 模型：DeepSeek`、`/设置 model=DeepSeek`、`/推理 高`、`/配置 推理强度 high` 和原有英文快捷命令。`/配置` 展示写法，`/配置 模型`、`/配置 推理强度` 查询会话状态。只规范化命令头和配置枚举，记忆、目标等正文保留大小写与全角文字。私聊显式 `/model`、`/reasoning` 的其他原生参数仍交给 Hermes；群聊配置仅支持会话级已知模型及档位，不开放全局配置。`/status` 明确显示配置默认值，当前会话实际值用原生命令查询。

“以后叫它土豆吧”只在本人五分钟内操作过当前会话的宠物时执行，否则询问对象。目标/梗只匹配本人的当前作用域条目，多个匹配会列出 ID；不猜测“昨天那个任务”或缺少正文的“这个梗”。引用、假设、否定和多步配置句保持普通聊天，未识别的群内斜杠命令提示 `/help`。非定向旁听不执行命令。插件本地操作先检查 Hermes 用户授权及命令权限；重复投递在修改状态前去重（若回执发送失败，请发一条新消息查询结果）。


| 输入 | 行为 |
| --- | --- |
| `/角色` | 查看角色与控制方式 |
| `活跃一点`、`自由聊天`、`恢复聊天` | 自由参与，无本地每分钟次数上限 |
| `少说一点` | 暂停普通插话，点名仍回应 |
| `安静一会儿`、`安静一下` | 暂停普通插话 30 分钟 |
| `/经历` | 查看自己与角色的近期共同经历 |
| `/梗簿`、`/记梗 内容`、`/忘梗 ID` | 查看群内确认的梗；仅创建者可删除自己的条目 |
| `/表达库`、`/学表达 场景 \| 短表达`、`/忘表达 ID` | 明确教授本群情境表达，相关场景才召回；仅创建者可删除 |
| `/待续 话题内容`、`/话题`、`/结束话题 ID`、`/忘话题 ID` | 保存、查看、关闭或删除本人的未完话题；只在再次聊到相关内容时续接 |
| `/目标 内容`、`/目标` | 保存或查看待办；每条有 ID、状态、来源和过期时间 |

| `/群投票 创建 题目 \| 选项A \| 选项B`、`/群投票` | 通用群投票；每群同时一个，最多五个选项，创建者可结束 |
| `/群投票 选择 POLL_ID OPTION_NO`、`/群投票 结束 POLL_ID` | 每人一票，可改选；结果不显示投票人，只有创建者可以结束 |
| `/宠物`、`/喂食`、`/摸摸`、`/宠物取名 名字` | 共享养成，饱食和开心随时间衰减，重启保留 |
| `/剧情 设定`、`/剧情` | 开始或查看持续的虚构冒险 |
| `/投票 1`、`/投票 2`、`/结束剧情` | 每人一票、可改票，两票且形成多数后推进；平票继续等待 |
| `/表情`、`/表情库`、`/表情 开心` | 查看本群分类库存或发送一张；优先群内收藏，开心/疑惑/无语/鼓励/晚安保留本地小电团图片回退 |

剧情采用有持续后果的四幕分支冒险：入口选择决定工坊或林间路线，后续可获得地图、电池、种子、同行伙伴等；修桥与绕行留下不同线索，最终选择点亮信标或解读档案。物资和伙伴会改变后续叙述及结局条件，消耗的物资从行囊移除。达到结局后停止接收推进投票，使用 `/结束剧情` 收起后可开始新冒险。每人一票、可改选，两票且形成多数后推进；现有剧情在下一次投票推进时迁移，保留设定和章节编号。

程序先原子保存选项后果、道具、伙伴、章节和命令回执，再按需调用模型丰富当前场景的旁白。模型不能修改游戏状态；回执同时展示确定性事件与独立标注的旁白。调用超时、输出不合法或模型不可用时仍返回可玩的已保存场景。重置、删除记忆、结束剧情或更新状态期间，晚到的旁白不得写回。剧情查询、未达到多数的投票和重复投递不触发模型调用；重启保留进度。普通聊天仍可由模型自由扮演，不能把自由文本冒充已保存的游戏变更。

### 情境表达与未完话题

这两类内容复用 `character_items` 的群/私聊隔离、所有者、保留期和删除机制，不新增数据库表，也不后台推送。

- 教表达：`/学表达 庆祝 | 土豆起飞了`，或直接说“学个表达：庆祝 | 土豆起飞了”。内置场景为庆祝、吐槽、鼓励、感谢、晚安；也支持“部署失败”等自定义场景。场景最多60字、表达最多80字；同一人重新教授相同表达会更新场景，保留使用次数和冷却。表达库是本群明确共享的内容，私聊使用独立空间；普通聊天不会自动收录成员原话。
- 留话题：`/待续 项目部署失败，下次接着排查`，或“下次接着聊：项目部署失败”。话题最多300字，仅当前成员在当前作用域可召回。不会推断别人有哪些未完成事项，也不会因机器人声称解决而自动关闭；用户用 `/结束话题 ID` 明确关闭，或 `/忘话题 ID` 删除。可说“看看未完话题”查看。
- 召回采用有界词面匹配，不宣称语义检索；每轮最多一条表达、一条本人未完话题。表达在认真求助时抑制；相关未完话题仍可用于排障，但“不要追问”“别再问”“别提旧事”会同时抑制两者。安静状态、停止记忆或关闭召回开关时不注入。
- 读取上下文不消耗冷却；只有成功送达且实际使用该表达/相关话题的回复才更新使用记录。默认冷却一小时，表达优先轮换使用次数较少的候选。模型可选择不用，不保证每次命中都输出。
- 表达保存90天，话题保存7天，每群每类最多100条；两类独立查询，不挤占共同经历的召回窗口。停止/忘记记忆会删除本人的条目，`/reset` 清除当前作用域全部角色条目。删除表达、关闭或删除话题会使旧回复失效，并重置当前原生会话上下文；知识库和其他人的独立条目保留。

配置位于 `plugins.entries.smart_group_qq.settings.character`：

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| `story_narration_enabled` | `true` | 新开或推进剧情时生成旁白；关闭后保留完整分支玩法 |
| `story_timeout_seconds` | `8` | 旁白模型等待上限，约束为1–15秒 |
| `conversation_recall_enabled` | `true` | 在普通对话中召回表达与未完话题；关闭不删除数据 |
| `recall_cooldown_seconds` | `3600` | 成功使用后的冷却，约束为60–86400秒 |

功能设计参考 MaiBot 的群聊表达、Pallas-Bot 的场景接话，以及 AstrBot 陪伴插件的未完话题思路；实现为本仓库独立代码，未引入它们的运行时、适配器或源代码。无需新增模型密钥或服务，旁白复用现有 Hermes 结构化模型接口。上线前仍需通过实际 QQ 测试群验收；本地测试使用模拟适配器与模型，不等同于真实平台验证。

通用群投票与剧情 `/投票` 独立，必须在授权群明确 @ 机器人执行。题目最多 200 字，选项最多 100 字，默认 24 小时过期。`/reset` 保留投票；`/忘记我` 删除本群本人投票，并级联删除本人创建的未结束投票。只展示本群结果，不展示成员身份。

### 群表情包收集与发送

GitHub 仓库发布订阅、后台探索和主动推送已删除；普通群聊参与、目标待办、宠物和剧情仍保留。目标不会后台执行网站研究或 shell，明确研究请求仍可调用原有 Hermes 工具。

`stickers.enabled` 启用群内表情库。自动收集只接受 QQ 适配器实际收到、通过群授权且落入配置缓存根的图片，不访问群友 URL，不收集私聊图片。视觉分类仅接纳高置信度、安全可复用的卡通/动物/情绪梗图，普通照片、真人照片、截图、文档、二维码和敏感内容拒绝；不确定也不入库。动图会校验并预览全部帧，归档时重新编码去掉元数据。

分类为开心、疑惑、无语、鼓励、晚安、赞同、惊讶、难过、感谢、庆祝。按内容去重、按群隔离；图片最多 512 KiB，默认每群 64 张、全库最多 256 张，保存 30 天。收藏来源只存成员伪名；停止记忆后不再收集该成员图片，并删除其来源；忘记我同样删除，其他成员独立分享的同图可保留。

`/表情 分类` 明确点一张，优先本群库存，轮换避免总发同一张。普通聊天的成功文字回复可以自动配一张相关库存图，默认至少间隔 60 秒；长回复、认真任务、用户不要图片、安静状态、私聊和静默/失败回复不自动发图。平台拒发时停止，发送结果不确定不重试；图库为空不额外生成或后台群发。

插件维护循环仍清理记忆、角色与表情过期数据，由真实 `gateway:startup` 生命周期启动，重复启动不创建第二个任务；验收继续检查本次启动后的 `maintenance_ready`。

### 角色数据与升级

数据库 schema 6 新增群表情、来源及发送冷却表；schema 5 的通用群投票、成员事实、角色玩法和知识库保留。迁移会移除旧 GitHub 推送的发现条目、固定自有目标和专属状态，不删除成员自建目标或聊天历史。原始成员 OpenID 不进入角色提示词或表情来源键。

Muse 风格的小栖更注重具体接话、独立观点和克制幽默，避免固定客服句式。每个群/私聊从自身持久化的成功互动记录派生有限的语气、详略与兴趣标签；至少三条记录才适应，最新三十条、每成员最多五条，不将原文写入高优先级人格。重启沿用记录，停止/忘记记忆、重置、到期清理同步撤回影响，不新增隐蔽画像；`/角色` 可查看本会话相处风格。

共同经历保存 30 天，目标 7 天，梗 90 天，每群每类最多 100 条；命令回执保存一天。`/停止记忆` 停止该成员的角色经历积累并清除其角色条目；重新授权前禁止保存目标或参与持久玩法。`/忘记我` 清除本人角色条目、关系、命令回执和可能包含衍生信息的群经历及共享剧情，恢复宠物默认状态；他人独立目标/梗保留。`/reset` 清除当前会话角色进度，知识库、群投票和表情库保留；Hermes 原生 `/new` 仅换会话，不清除持久角色。

部署前按原流程备份数据库，回滚至旧 schema 必须恢复升级前配套快照。

## 模型

Hermes 只注册 `sub2api_deepseek` 一个供应商，以同一把服务器密钥和 OpenAI Chat Completions 调用 `deepseek/deepseek-v4.1-flash` 与 `xiaomi/mimo-v2.6-flash`。DeepSeek 保持默认，`/mimo` 与 `/deepseek` 只切换当前会话。两模型的推理强度覆写均为 `low`，请求显式携带顶层 `reasoning_effort`。DeepSeek 与 MiMo 的注册上下文预算分别为 1000000、131072 token；QQ 上下文超过 80000 token 时后台固定使用 DeepSeek 与 `low` 生成摘要。

部署保留现有会话、历史和持久的会话级模型设置，不为升级执行批量 `/new`。Hermes 原生 `/reasoning` 是会话运行状态，不写入 SessionStore 路由；重启后按模型配置恢复档位，不宣称跨重启持久化。`/model`、`/reasoning` 查询实际设置。图片保持原生内容块，不配置自动模型回退。群聊不发送 “Interrupting current task” 忙碌确认。打断后模型若仍输出 `action`/`message` 信封，发送前取出正文并做 QQ 纯文本清洗。

QQ 自动压缩由独立协调器接管：轮次开始与完成后检查 80000 token 阈值，后台生成摘要不阻塞回复；完成后在下一轮持有会话锁的安全边界，通过 Hermes 原子事务建立新会话，仅带入一条摘要和最新 10 条历史消息。工具协议转换为历史文字，避免孤立 tool call。摘要期间新增不超过 10 条可直接保留；更多新增先增量归纳，绝不静默丢弃未摘要内容。群与私聊互相隔离。摘要失败/超时、历史变化、`/new`/`/reset` 或事务水位不匹配时不清空旧对话，失败至少间隔 60 秒重试；重启丢弃未提交候选并从持久原文重新准备。80000 是触发阈值，不是请求硬上限；最新 10 条本身过大时保留原会话并记录告警，不强行截断。手动 `/compress` 仍由 Hermes 原生命令处理。群记忆独立在 40 条新消息且距上次刷新至少 300 秒时整理；或至少 4 条新消息的最老一条等待 1200 秒后整理。

插件 pre-dispatch 使用异步 hook。`/reset`、`/纠正记忆`、`/停止记忆` 和 `/忘记我` 在发送确认前 await Hermes 原生 reset 边界，失效旧 generation、清理 agent/cache/会话安全状态、触发 hooks，再更新持久路由；不得直接调用 SessionStore.reset_session 替代这条生命周期。原生用户授权或命令权限接口缺失时，本地命令不执行副作用，由中央 pairing/拒绝处理。

已开始的群摘要任务独立于新任务门槛：失败任务按退避时间重试，分批剩余消息会继续处理，即使群里没有新发言；有效租约期间不重复执行。模型失败时保留最后一次有效摘要及其游标，未整理原文仍保留待重试，不用聊天原文尾部覆盖已有摘要。摘要输入预算小于首条消息时对该条限长，避免游标永久停滞。成员事实的来源原文按保留期清理后，仍用持久来源序号阻止较旧提取覆盖较新事实。

## 部署

生产目录：

- 应用与 Compose：`/opt/qqbot-hk`
- 持久数据与秘密：`/opt/qqbot-hk-deploy`

安装脚本先对 `plugin-data/smart_group_qq/data.db` 执行完整性检查和 SQLite 在线快照；镜像构建及离线烟测成功后才停止目标容器，在服务器以同一时间戳备份 plugin DB、`state.db`、`sessions.json`、旧配置、插件、hooks、cron 与 Compose，并记录旧镜像 ID，之后安装新配置并切换镜像。配套快照保存在 `/opt/qqbot-hk-deploy/backups/hermes-sessions`，保留现有 QQ 会话：

```bash
bash /opt/qqbot-hk/scripts/install-server.sh
# 安装脚本已自动执行同一份完整验收；需要独立复查时可再次运行：
bash /opt/qqbot-hk/scripts/verify-server.sh
```

`install-server.sh` 会校验固定公告目标列表，保留配置模板的群专属通配授权，移除旧沙箱路由和包括私聊在内的全员放行开关，安装 SOUL/plugin/schedule/reconciler，构建固定摘要派生镜像，只停启 `hermes-qqbot`，等待健康、运行 cron 对账并完成验收。可用 `QQBOT_IMAGE=qqbot-hk/hermes-agent:<固定提交>` 指定不可混淆的发布镜像标签。旧插件副本在启动前移到部署备份目录，避免 Hermes 将 `plugins/*.old` 当作另一份活动插件加载。源码配置不含真实 OpenID 或 API key。

`verify-server.sh` 验证基础摘要/补丁标签、DeepSeek 与 MiMo 的 OpenAI Chat Completions 路由及显式推理强度、语音禁用、单把 Sub2API key 注入、DeepSeek 文本/识图与 MiMo 文本、80k 异步压缩与 10 条/5 图策略、QQ 中间输出关闭、最终输出补丁、聚合与分段预算、工具集与文件边界、容器健康、QQ 生产网关、私聊策略、插件、白名单、owned cron 及 SQLite 表结构。镜像构建还使用临时合成 SessionDB 验证会话原子发布及水位 CAS；不读取生产聊天内容。

部署后验证任意已加入的新群通过适配器与中央群授权，未批准私聊仍被拒绝或进入 pairing，两名成员共享本群上下文且不串群。群管理员打开“接收所有消息”并确认平台实际投递后，再验证：有内容的分享按需接话、纯表情不无意义抢答、多人延续话题、自由参与、手动安静与恢复、短句分条、重复事件只处理一次、非 @ 管理命令不执行、近期旁听能作为后续 @ 的上下文。安全表情可以静默收藏，聊天配图只接在成功文字回复之后；不会进行仓库后台推送或单独表情群发。

## 回滚

恢复上一个精确代码/镜像和部署前备份；应停止目标容器并同时恢复对应 schema 的 plugin DB、`state.db`、`sessions.json` 及配套配置快照，不应直接覆盖运行中的 SQLite。本版本 SQLite schema 为 `6`；回滚本次升级使用 schema 5 的整组快照，旧 schema 4 快照仍按原保留策略留在服务器。旧版代码会拒绝更高 schema，不能只切换旧镜像，也不得通过删库初始化解决兼容问题。cron 回滚只处理 `smart-group-qq::` 前缀任务，不覆盖整个 Hermes cron。备份与原始生产数据始终留在服务器，按独立保留策略管理。
